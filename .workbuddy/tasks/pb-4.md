# pb-4（L4）团队跟踪视图

- 级别：S1 ｜ blockedBy：pb-2 ｜ 状态：⬜待分配
- 方案章节：4.4 / 6 / 9-B4 / 10-AC-D

## 目标
任一工单可定位「卡在哪个团队、哪个环节、找谁」，且跨团队不重复计数。

## 范围
- 团队子行 `pmwb_pb_track_team`（工单 × 团队，唯一约束）；团队解析走现网活跃厂家团队 + 人员中台目标系统映射（`active_team_systems()`），解析失败进**可见兜底**「待补团队」，不静默丢弃。
- 主行 / 子行双层口径显式分离：版本统计按主行、团队视图按子行；卡片数与下钻数同源，禁止出现「卡片 8 / 下钻 9」。
- 团队矩阵、按团队/环节/超期筛选、下钻抽屉复用页面唯一组件；准入 / 顺延 / 反馈列；批量更新进度入口（对接 pb-7）。

## 边界
- 不新建团队字典；不复制多负责人拆分（复用 `utils/owners.py` + `utils/owner.js::ownerList`）。
- 不改主行状态语义（pb-3 唯一写入）。

## 验收
- 一个工单挂 3 个团队：版本概览计 1、团队视图计 3，两处口径有显式标注。
- 矩阵任一数字下钻结果与矩阵计数一致且带同一筛选条件。
- 团队解析失败的行出现在「待补团队」清单，不消失。

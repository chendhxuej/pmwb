# pb-2（L2）候选池与纳入

- 级别：S1 ｜ blockedBy：pb-1 ｜ 状态：⬜待分配
- 方案章节：4.3 / 5.2 / 9-B2 / 10-AC-B

## 目标
把「符合条件、未闭环、未纳入」的需求与运营 BUG 工单算成候选池，三处入口纳入后生成全局唯一的跟踪主行。

## 范围
- `services/paiban_candidate.py`：唯一筛选规则（需求侧取状态/级别/期望上线日；BUG 侧取问题大类=BUG、状态未闭环）；命中与排除原因都必须可复算、可展示。
- `pmwb_pb_track` 主行（工单锚 = 类型 + 源唯一编号，全局唯一）、纳入方式 / 时间 / 人、在册状态（在跟 / 已移出墓碑）。
- 三入口：候选池批量确认纳入、工单详情行内纳入、幂等全量 `sync`（同一工单不产生第二行）。
- 源消失 → 置「已移出」留行不删；采集失败来源本轮不参与源消失判定并显式告警（参考现网任务中心口径）。

## 边界
- 只读源模块，禁编辑需求/BUG 本体；**不回写运营工单**；不接任务中心 7 collector。
- 不做环节状态、团队子行、准入判定（pb-3/pb-4）。

## 验收
- 同一工单连续 sync 两次主行数不变；候选池每条有命中或排除原因。
- 源删除后行仍在且 `active=0`，列表默认排除、可追溯。
- 候选池列表与下钻明细同源（展示字段=筛选字段=同一口径）。

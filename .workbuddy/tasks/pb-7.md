# pb-7（L9）反馈同步与便捷录入（老大重点关注）

- 级别：S1 ｜ blockedBy：pb-5, pb-6（接口先约定可并行）｜ 状态：⬜待分配
- 方案章节：4.9 / 7.7 / 8 / 9-B7 / 10-AC-J

## 目标
厂家团队邮件反馈、电话/微信/会议口径能**低摩擦进系统**，且每次进度/风险变更可追溯到原文与来源、可回滚。

## 范围
- 四通道：**A 邮件结构化回执**（按督办批次号 + 每单唯一回执码只读匹配邮件中心收件箱，Message-ID 幂等）、**B 团队批量更新进度**、**C 行内「记一笔」**、**D 电话/微信/会议代录**（必填来源与转述人）。
- `pmwb_pb_feedback`：来源、原文、Message-ID、解析结果、结构化四字段、建议变更、采纳状态（自动采纳 / 待核对 / 已驳回）、**采纳前值**、操作人/时间、回滚标记。
- 铁律：结构化行**自动采纳**；**自由文本只出建议进待核对、绝不自动改状态**；回退走必填原因校验；风险按 (工单,风险类型,未消除) 合并更新（调 pb-5）；冲突保留全部原文，**不取最后一条覆盖**；采纳后重算超期 / 督办 / 硬门禁 / 回执状态；保留采纳前值支持一键回滚。
- 通道不可用 → 标「待自动补跑」，页面通道照常可用，**不转人工判定、不降级关键词**。

## 边界
- **不复用**周反馈导入的 ISO 周 / 状态只进不退 / 标签归类；批次号路由隔离。
- 反馈链路禁自动真发邮件；不做 NLP 自由判定，解析规则闭集。

## 验收
- 结构化回执自动采纳且采纳前值可一键回滚；自由文本只进待核对不改状态；同一 Message-ID 重复拉取不产生第二条。
- 两条冲突反馈原文都保留；采纳/驳回后页面计数与待核对量同源。
- 通道不可用标记「待自动补跑」，不出现「转人工」入口。

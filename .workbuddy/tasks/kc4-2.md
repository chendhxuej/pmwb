# kc4-2 主笔记自动回流引擎 sync_main_note_from_links

- 分支：认领后建子分支 `feature/kc4-2-main-note-sync`，PR 合入 `feature/kc4-knowledge-hub`（Vicky2号 审查合版）
- 级别：S2
- 参考：`docs/kc3_knowledge_hub_plan.md` §4.2 / §5(kc4-2)

## 目标
新增 `sync_main_note_from_links(domain_code)`，遍历该领域关联表，把交付物 / 规则 / 变更轨迹 / 时间线重算回写主笔记「自动区」，实现「需求交付 → 业务知识自动更新」。这是缺口 A（内容回流断链）的核心修复。

## 分级回写策略（防误写业务事实）
- §2 产商品 / §3 业务流程：仅「需求 `status=closed` 且勾选 `product_changed`/`process_changed`」才回写。
- §4.1 场景规则：需求用户故事 `rules` 非空即回写（结构化、带需求编号可追溯，风险低）。
- §6 交付物 / §8 业务时间线：全部放开（交付物来自需求直挂文件；时间线为 link 客观记录）。
- §1 概述 / §4.2 通用规则 / §7 关联系统：**人工区，系统永不自动写**。

## 落点文件
- `backend/services/obsidian_link.py`：新增 `sync_main_note_from_links`；主笔记模板分「人工区 / 自动区」标记。
- 自动触发：需求关闭 / 归档端点后调用 `sync`。
- 手动入口：前端「同步业务知识」按钮 → `POST /api/v1/knowledge/sync-main-note`。

## 验收
- 闭合一需求（勾 `product_changed`）→ 主笔记 §2 / §8 出现该需求条目；人工区 §1 / §4.2 / §7 不变。
- 未勾变更标记的需求不污染 §2 / §3。
- 单测：mock 需求 `closed+product_changed`，断言 §2 含该需求。

## 依赖
- blockedBy **kc4-1**（link 需 `event_type/event_date/summary`）。

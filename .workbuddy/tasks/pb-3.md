# pb-3（L3）四环节状态机 + 准入判定 + 自动顺延（核心）

- 级别：S1 ｜ blockedBy：pb-1, pb-2 ｜ 状态：⬜待分配
- 方案章节：4.3 / 4.6 / 5.3 / 5.8 / 5.8.1 / 5.9 / 9-B3 / 10-AC-C, I

## 目标
四环节推进 → 按时准入 → 上线结果登记 → 没上成自动顺延下一版，循环到成功上线。

## 范围
- 四环节 `plan_confirm / dev / test / wait_release`，主行当前环节 = 最慢团队子行，**禁手工直接设**；回退必填原因并写流转留痕；新域注册 `status_registry.py` + 前端 `/meta/status-domains`。
- 准入四态 `待判定 / 已准入 / 未准入（默认已顺延） / 人工例外准入`；判定事实取主行进入「等待发布」时间（= 最慢团队完成测试），时点 = 发布日 − N（CRM 7 自然日）。
- 上线结果四态 `已上线 / 未排进版本 / 上线失败 / 取消` + 未出结果；有「影响上线且未消除」风险时**硬门禁阻断**「已上线」。
- 默认自动顺延：未准入 / 未排进版本 / 上线失败 → 自动改挂下一版（唯一 `next_plan()`）、准入复位、次数 +1、原属版本链追加、环节回滚、自动登记风险、全口径重算；**主行唯一不关闭**，终态仅「已上线」或人工「取消」。顺延 ≥2 重点、≥3 异常清单，**不自动发邮件**。
- 手工例外放行（老大 11-18 拍板）：单据级二选一「确认顺延（默认）」/「例外放行留本版」；必填**原因（闭集）+ 操作人 + 时间 + 原判定事实四要素**，写变更日志与流转留痕；不批量、不自动、不做静默后门；可撤销回滚到未准入并按默认顺延；采纳前值保留。
- 统计：人工例外单计入本版分母，**不计入按计划上线率分子**，单列清单。

## 边界
- 不做部分上线；不接任务中心；不改源状态语义；不回写运营 BUG 工单。
- 准入模式只从版本计划读（pb-1 契约），**禁工单上另设「允许临时合入」开关**。

## 验收
- CRM −8/−7 天 → 已准入；−6 天 / 临时合入 → 未准入且**默认已自动顺延**；例外放行必须填原因才能提交，留痕四要素齐全，撤销后回未准入并顺延。
- 上线失败后切到下一版仍能看到同一主行；顺延次数、原属版本链、参与记录完整。
- 例外放行单不进按计划上线率分子；硬门禁对未消除风险生效。

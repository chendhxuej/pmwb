# pb-6（L6）团队 × 类型一键批量督办 + 回执锚点

- 级别：S1 ｜ blockedBy：pb-4 ｜ 状态：⬜待分配
- 方案章节：4.8 / 7 / 7.7 / 9-B6 / 10-AC-F

## 目标
一次操作覆盖某团队某类型（需求 / BUG）的全部应督办对象，且每单能查「发了几次、上次何时、对方回没回」。

## 范围
- 规则圈定：**9 条纳入 / 7 条排除**（方案 7 章），含停滞 7 天、环节超期、顺延重点对象、连续顺延异常；排除已上线、取消、墓碑、无有效版本计划、解析失败收件人等。
- `pmwb_pb_supervise_batch` + `pmwb_pb_supervise_item`：批次号、团队、类型、版本、生成时间、操作人、逐单回执码、发送状态、跳过原因、回执状态。
- 邮件组稿：每工单**唯一回执码 + 批次号**，四字段（当前环节 / 实际进度 / 风险事件 / 承诺时间）回执区；收件人只绑**一条**现网解析链（`utils/email.py::resolve_contact_emails`），自动抄送走 `AUTO_CC_RULES`。
- 预览 → 确认发送 → 结果记录；24h 冷却 + **5 类例外**（新增「收到有效反馈但仍超期」）；重复督办按 (工单, 团队, 类型, 版本) 去重可复算。

## 红线
- **AI 自测一律 `dry_run`**，不落真发；真发仅老大页面显式 `confirm_send=true`（`dispatch_email`）。
- 禁 curl / 脚本向真实收件人发信；禁前端裸 URL 下载。

## 验收
- 同一批次内重复工单不出现两次；24h 内二次督办被冷却拦截并给出剩余时间；5 类例外可逐条复算。
- 每单有回执码，批次可查回执状态；dry_run 下 `sent_emails` 只落库不真发。

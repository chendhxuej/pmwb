# kc-2-2 业务知识主笔记 + 按领域浏览重构

> 批次：kc-2 批次二（依赖 kc-2-1 关联表与基础设施）
> 级别：S2
> 分支：`feature/kc-2-2-domain-main-note`
> 依赖：kc-2-1 ✅

---

## 1. 背景上下文

现有「按领域浏览」(`DomainKnowledgeView.vue`) 只按 `domain_code` 把 `pmwb_knowledge_item` 平铺聚合，**无法区分主笔记/子笔记/过程性笔记**，也没有一个领域的「知识总览」视图。用户理想状态：从业务知识主笔记能看到该业务全部信息，并能便捷跳转到关联的需求/工单/会议时间线。

本任务建立主笔记管理能力 + 重写按领域浏览，让"业务对象为中心"的视图落地。

---

## 2. 目标

1. 后端提供领域知识聚合接口：返回某领域主笔记 + 子笔记分组 + 过程性关联（需求/工单/会议/运营）时间线。
2. 重写 `DomainKnowledgeView.vue`：左侧领域树，右侧主笔记卡片 + 子笔记分组（按 `sub_type`）+ 过程性内容 Tab（时间线）。
3. 主笔记卡片支持：应用内预览、Obsidian 打开、编辑 Markdown、新建子笔记。

---

## 3. 精确改动范围

### 后端
- `backend/services/business_domain.py`：新增 `get_domain_knowledge(domain_code)`，按 `pmwb_knowledge_link` + `domain_code` 聚合，区分：
  - `main_note`（note_type=business_main）
  - `sub_notes`（note_type=sub_note，按 sub_type 分组）
  - `process_timeline`（source_type ∈ requirement/ticket/operation/meeting，按时间倒序）
- `backend/routers/knowledge.py` 或 `business_domain.py`：
  - `GET /knowledge/domain/{domain_code}` → 上述聚合结构。
  - `GET /knowledge/domain/{domain_code}/timeline` → 过程性内容时间线（可分页）。
- `backend/services/knowledge.py`：新增 `create_main_note(domain_code)`（基于方案 §4.1/4.2 模板生成主笔记 Markdown + frontmatter + 索引），供 kc-2-1 前端入口与本项目复用。

### 前端
- 重写 `frontend/src/views/DomainKnowledgeView.vue`：
  - 顶部领域卡片（保留现有结构）。
  - 进入领域后：左侧主笔记卡片 + MOC 链接；中间子笔记按 `sub_type` 分组（产商品资费/SOP/规则/变更轨迹/交付物）；右侧/下方过程性内容 Tab（需求、开发工单、会议、运营工单），数据来自聚合接口。
  - 主笔记卡片操作：预览、Obsidian 打开、编辑 Markdown（调 Obsidian URI 或内联编辑器）、新建子笔记。
- `frontend/src/router/index.js`：可选新增 `/knowledge-center/domain/:domain_code` 详情路由（或在现有 DomainKnowledgeView 内用 state 切换，优先不增路由）。

---

## 4. 验收标准

- 打开「一网通宽带」领域：能看到主笔记、子笔记分组、关联需求/工单/会议时间线。
- 主笔记可在应用内预览，可一键在 Obsidian 打开。
- 新建子笔记后，按领域浏览对应分组立即出现该子笔记。
- `pytest` + `vite build` 通过。

---

## 5. 禁止项

- 禁止破坏现有"按领域浏览"的领域卡片入口。
- 禁止在聚合接口里做重逻辑写操作（只读聚合）。
- 禁止引入新 UI 框架，复用 Element Plus + 现有组件。

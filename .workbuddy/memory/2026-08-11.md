## 彻底解决沙箱 git 环境问题 + enlarge-input 功能收尾

### 根因（前序会话遗留，今日彻底定位）
沙箱 `.git` 在**每条命令之间**被重置回基线：`HEAD` 被打回 `feature/enlarge-input` 这个从未有提交的空分支、`index` 被清空（`ls-files=0`）。导致：
- 任何「先 reset 索引→下条命令 add」多步流程必把全仓库当新增暂存（413 文件）。
- `git checkout`/`checkout -b`/`branch` 等分支切换命令会在命令内再次清空 index。

### 彻底解决方案（单命令法，已验证）
在**同一条** bash 命令内完成：
`git symbolic-ref HEAD refs/heads/main` → `git reset --mixed main`（同命令内 ls-files 恢复 409）→ `git add <精确路径>`（不 checkout）→ `git commit` → `git push origin HEAD:refs/heads/feature/enlarge-input`（不切本地分支）。
- add 后用 `git diff --cached --name-only | grep -vE "^(frontend/src/|scripts/...)"` 断言，有多余即 `git reset -q` 中止。

### 结果（已推 origin）
- commit `2a36498`「feat(frontend): 输入框点击放大编辑 EnlargeInput 全局适配」，34 文件 / +529 / −194。
- 3 新文件：EnlargeInput.vue、EnlargeInputDialog.vue、useEnlargeInput.js；+ scripts/enlarge-input-codemod.mjs；+ 28 个 codemod 改名文件（<el-input>→<EnlargeInput>）；+ RequirementDeliveryView 故事标题修复。
- 远端分支 `github.com:chendhxuej/pmwb.git` 的 `feature/enlarge-input` 已创建（[new branch] HEAD -> feature/enlarge-input）。
- 本地 main 的该 commit 会被环境回滚，但远端持久，老本机 `git fetch`/提 PR 合版即可。

### 验证

- grep 复核 0 残留 `<el-input`。

## UI 优化回归修复（三处，老大反馈）

### 第一次修复失败的真实根因（关键复盘）
上次脚本把统计卡里的 `v-countup` 从**指令属性**错置成了 div 的**文本子节点**：
`<div class="stat-value"> v-countup="item.value"></div>`（注意 `"> v-countup=` 里的 `>`）。
Vue 不把它当指令 → `countup.mounted` 永不触发 → 统计值直接把字面文本 ` v-countup="..."` 渲染出来，即老大看到的"统计数字异常"。

### 修复（已二次验证通过）
1. **统计卡修复（#1）**：脚本批量把 `"> v-countup="` 还原成属性 `" v-countup="`，9 视图共 30 处；指令 `frontend/src/composables/countup.js` 仍管自己的 `<span class="cu-num">` 子节点作唯一写入源。`main.js` 已注册。
2. **个人待办标题点击（#2，最终方案，老大拍板）**：
   - 弃用"跨路由跳转 `/operation?issue=`"（老大不喜欢跳转）。
   - 也弃用"页内 `el-drawer` 详情"（老大反馈没生效、且点 `related_type=meeting` 的行会 `router.push('/meeting')` 跳到会议中心，正是现象根因）。
   - **最终**：标题点击 = 与「编辑」按钮完全同一 handler。模板 `@click="handleEdit(row)"`（原 `@click="row.related_id && openLinked(row)"`）。`handleEdit` 打开 `dialogVisible`（待办编辑弹窗，标题"编辑待办"），即老大所指"代办工单详情页面"。
   - 已彻底移除抽屉及其死代码：`openLinked`/`openWoDetail`/`woDrawerVisible`/`woDetail`/`woLoading`/`fmtDate`、`<el-drawer>` 模板块、`.wo-*` 样式、`operationApi` 引入。
3. **运营工单标题列加宽（#3）**：`WorkOrderView.vue` 标题列 `min-width="200"→"380"`，保留 `show-overflow-tooltip`。

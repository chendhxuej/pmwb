## 工单列表「创建时间/计划完成」不显示 — 根因分析 + 修复

### 现象
任务中心及各工单列表的「创建时间」「计划完成」列不展示（显示 `—`）。

### 分析结论（逐项核对）
1. **源头数据有值**：直接查 DB 抽样，pmwb_todo / operation_issue / meeting_action / key_work_member_task / milestone 的 created_at 与计划完成字段均为真实日期；dev_ticket 表 **total=0（空表）**。
2. **前端列绑定正确**：TaskCenterView 第152行 `created_at` 列、第155行「计划完成」列均正确；各独立列表页（Todo/Operation/WorkOrder/MeetingActions/KeyWork）也已绑好。
3. **后端代码正确但进程旧**：API 实测 —— `/todos` `/operation/issues` `/meetings/actions` 均返回 `created_at`；唯独 `/task-center/tasks` 返回的 JSON **完全没有 created_at 字段**。因 task_center 是最近才加 created_at 的模块，运行中的后端进程（原 PID 23016）加载的是加字段前的旧代码，**没重启**。
4. **dev_ticket 映射遗漏**：collect_dev_ticket 里 `due_date=None` 硬编码，未映射 `go_live_date`（实际计划完成=实际上线日期）。

### 修复动作
- **重启后端**：`taskkill /F /PID 23016` → 看门狗拉起新进程（PID 20896），`/task-center/tasks` 立即返回 `created_at`。根因=进程未重启，非源头/前端问题。
- **改 task_center.py**：`collect_dev_ticket` 的 `due_date=None` → `due_date=r.go_live_date`（go_live_date 为 Date 类型，直接映射）。
- **验证**：Puppeteer 跑任务中心，创建时间列显示真实日期（2026-08-01/07-31/07-30…），计划完成列有值显日期、无值显 `—`，零控制台错误。截图 tmp_smoke/v5_taskcenter_dates.png。

### 各列表参数存在性结论
- created_at：**所有源表都存在该字段**；仅任务中心聚合接口因进程旧未吐出（已修复）。
- 计划完成字段名各异但**均存在**：todo.due_date / operation.resolve_date / dev_ticket.go_live_date / meeting_action.due_date / key_work.due_date。个别记录为 null 是**数据未填**，非字段缺失。
- dev_ticket 列表/任务中心开发工单 tab 为空：表无数据（尚未录入开发工单），非代码问题。

### Git
- 提交 `d973cbe`（dev_ticket 映射修复）已推送到 `feature/ui-3-dashboard-polish`。
- 坑：`.git/refs/heads/feature/` 目录被沙箱文件系统搞丢，导致 push 报 refspec 不匹配；`mkdir -p .git/refs/heads/feature && printf '<sha>\n' > .git/refs/heads/feature/ui-3-dashboard-polish` 重建引用后 push 成功。

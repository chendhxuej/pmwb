## 后端崩溃循环修复（看门狗日志反馈）
- **现象**：看门狗日志持续 `Backend(8000) down -> starting uvicorn`（每 ~17s 一次），MySQL 全程 UP、其余服务正常。
- **根因**：`backend/routers/supervise.py:15` 错误导入 `from services.operation import operation_service`，
  `services/operation.py` 实际只导出 `operation_issue_service`，符号名写错导致导入期 `ImportError`，uvicorn 起不来→看门狗无限重启。
  该错误由提交 `59c4e8f feat: add supervise email service (sup-2)` 引入。
- **修复**：改为 `from services.operation import operation_issue_service as operation_service`（别名，避免动第45行调用），
  其余两处引用（routers/operation.py、services/obsidian_link.py）本就用正确名，无需改。
- **验证**：手动 `uvicorn main:app --port 8099` 已越过导入阶段（仅测试环境连不上 3306），导入链干净；主机看门狗下一轮（≤15s）拉起即用修复代码，自动恢复。
- **注意**：看门狗 `spawn()` 把 uvicorn stdout/stderr 丢进 DEVNULL，崩溃报错不可见，仅表现为反复 down。下次类似"后端一直 down"，优先手动带输出拉起抓 traceback。

**问题 1：状态切换报 405**
- 截图：顶部红条「Request failed with status code 405」，点状态徽标 → 选「进行中」即报 405。
- 根因：`frontend/src/api/todo.js::updateTodoStatus` 用的是 `request.patch('/todos/{id}/status')`，但 `backend/routers/todo.py::update_todo_status` 是 `@router.put`。PATCH 路由不存在 → 405。
- 修：前端 `updateTodoStatus(id, status)` 改 `request.put('/todos/${id}/status', { status })`（body 传 `{status}` JSON，对齐 `TodoStatusUpdate` schema）。

**问题 2：列表「几行异常展示红竖线」**
- 截图：已完成 / 未超期的行也带红条 + 左侧 3px 红竖。
- 根因：`backend/services/todo.py::_check_overdue` 只在 `create/update/update_status` 写 DB；`list_with_filters` 与 `get` 直接返回 DB 里 `is_overdue` 历史值。跨天后没再触发 create/update 的行 → is_overdue 残留 1；done 态也没把 is_overdue 清零。前端 `rowClassName` 又只看 `row.is_overdue`，对 done 态无防御。
- 修：
  - `services/todo.py` 新增 `_refresh_overdue_inplace(items)`，**内存里**把 obj.is_overdue 校正为「今天 vs due_date」实时结果（不写库），保证 list/get 接口返回的 `is_overdue` 与当日真实状态一致。
  - `list_with_filters` 与 `get` 在序列化前调用 `_refresh_overdue_inplace`。
  - `get_stats` 的 overdue 计数从 `is_overdue==1` 改为 `status.notin_(done,cancelled) AND due_date < today`，统计也实时化。
  - 前端 rowClassName 不再改（dueTone 已对 done 返 none，配合实时化的 is_overdue，前端不会再误画红条）。

**铁律（新增）**：
- **HTTP 谓词必须前后端一致**：写前端 API 时必须 grep `routers/*.py` 的 `@router.<verb>` 与 schema body 形态同步对照，PATCH vs PUT 不通用。
- **「DB 字段做缓存型快照」不可信**：任何带状态/时间语义的字段（如 `is_overdue`），list/get 必须实时算（内存里校正即可，不写库），避免跨天后 UI 与真实情况不一致。`is_overdue` 是典型反面教材。

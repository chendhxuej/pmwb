## 2026-08-06 用户故事自动生成策略优化

### 背景
老大反馈"需求与交付"模块的用户故事自动生成策略有问题，不符合公司内部最新管理要求。基于《用户故事拆分边界管理规范》做适配优化。

### 改动内容

**新增文件（3 个）**：
- `backend/services/storygen_rules.py` — 规则引擎 v2（合并优先策略）：角色识别、场景边界检测、闭环检测、差异显性化
- `backend/services/storygen_llm.py` — LLM 客户端（OpenAI 兼容协议）：支持 Ollama/DeepSeek，含合规校验器
- `backend/services/storygen_prompt.py` — LLM Prompt 模板：编码全部 5 条拆分原则 + 4 条允许条件 + 4 条禁止红线 + few-shot 示例

**修改文件（6 个）**：
- `backend/core/config.py` — 新增 8 个 LLM 配置项（默认关闭）
- `backend/.env` — 新增 LLM 配置示例
- `backend/services/requirement_delivery.py` — `generate_user_stories()` 改为策略路由（rules_v2/rules_v1/llm）
- `backend/schemas/requirement_delivery.py` — `UserStoryGenIn` 新增 `strategy` 字段，`UserStoryGenOut` 新增 `strategy_used`
- `backend/routers/requirement_delivery.py` — 路由适配 strategy 参数
- `frontend/src/views/RequirementDeliveryView.vue` — 生成按钮改为下拉策略选择 + 预览确认流程 + 策略标签
- `frontend/src/api/requirement.js` — API 入参新增 strategy

**测试**：
- `backend/tests/test_requirement_delivery.py` — 新增 4 个测试用例（v1 兼容、v2 合并、角色检测、默认策略）
- 全量回归：**119 passed**（+4 新增）/ 4 failed（同基线）| 前端 vite build 干净 | vitest 7/7

### 核心变更说明
1. **旧版行为（rules_v1）**：按行数/人天机械拆分，上限 8 条 — 已标记为不推荐，作为兼容模式保留
2. **新版行为（rules_v2，默认）**：合并优先策略，检测角色/场景/闭环，同角色同场景合并为 1 条，上限 5 条
3. **LLM 模式**：需先配置 `US_STORY_LLM_ENABLED=true`，支持本地 Ollama 或其他 OpenAI 兼容接口；失败自动降级到 rules_v2
4. **前端体验**：生成后先预览不落库，需手动点击"确认落库"；显示策略来源标签

- `backend/.env` — LLM 配置块更新为 Kimi 专用指引（含 API Key 获取地址、模型选择说明）
- `backend/services/storygen_llm.py` — 全面重写：
  - 新增 `check_llm_available()` 健康检查函数（轻量探针请求验证连通性）
  - 增强 JSON 提取：支持 Kimi 输出中混入中文引导语（"好的，以下是..."）的清洗
  - 新增输入长度预警（8K 模型约 6000 字安全线）
  - 合规校验增强：硬上限 5 条 + 禁止技术维度拆分关键词检测

- `backend/routers/requirement_delivery.py` — 新增 `GET /delivery/llm-status` 端点
- `frontend/src/api/requirement.js` — 新增 `getLlmStatus()` API
- `frontend/src/views/RequirementDeliveryView.vue` — 下拉菜单动态显示 LLM 状态：

### Kimi 超时修复（第四轮）

**问题**：网页端"Kimi 智能拆分"报错 `timeout of 30000ms exceeded`。根因：前端 axios 全局超时 30s，但 kimi-k2.6 带 reasoning 实际响应 ~33s，刚好卡死。

**改动内容**：
- `frontend/src/api/requirement.js` — `generateUserStories()` 函数对 `strategy === 'llm'` 单独设置 `timeout: 120000`（120s），其他策略保持 30s
- `backend/.env` — `US_STORY_LLM_TIMEOUT` 从 60 改为 120
- `backend/core/config.py` — `US_STORY_LLM_TIMEOUT` 默认值从 60 改为 120
- `backend/services/storygen_llm.py` — 健康检查超时从 15s 改为 30s（kimi-k2.6 带 reasoning 即使 ping 也需 ~14s）

**端到端验证**（HTTP API 真实调用）：
- 健康检查 14.1s ✅（30s 超时内）
- 完整生成 32.8s ✅（120s 超时内），`strategy_used: "llm"`，2 条故事（运营人员+管理员正确按角色拆分）
- 测试套件 12/12 passed，vite build 干净，vitest 7/7

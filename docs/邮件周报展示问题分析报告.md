## 二、根因分析：为什么之前多次优化无效

### 2.1 核心根因：非法 HTML 属性 + 不兼容 CSS 组合

当前代码在核心容器 table 上同时存在三个问题：

```html
<table width="100%" max-width="680" ... style="...margin:0 auto;">
```

| 问题 | 说明 | 在 Foxmail/Outlook 中的表现 |
|------|------|------------------------------|
| `max-width="680"` 作为 HTML 属性 | `<table>` 标准属性没有 `max-width`，只有 `width` | Foxmail 基于 Trident/Edge 渲染，可能保留该属性并当作某种宽度限制处理；Outlook 桌面版会直接忽略，但某些版本会错误解析 |
| `margin:0 auto` | CSS 居中在 Outlook 2007+ 和 Foxmail 中基本不被支持 | 完全失效，表格默认左对齐 |
| `width="100%"` 与 `margin:0 auto` 同时存在 | 没有固定宽度的块级元素无法通过 margin 居中 | 即使 margin 生效，由于 width=100% 已经撑满，auto margin 也无意义 |

**结论：之前把 `width="680"` 改成 `width="100%" max-width="680" margin:0 auto` 是一个“看起来合理、实际在邮件客户端里行不通”的修改。**

### 2.2 邮件客户端渲染特性

| 客户端 | 对 `max-width` 支持 | 对 `margin:0 auto` 支持 | 对 `width="90%"` 支持 | 对 `<td align="center">` 支持 | 备注 |
|--------|---------------------|--------------------------|------------------------|-------------------------------|------|
| Outlook Windows（Word 渲染引擎） | ❌ 不支持 | ❌ 不支持 | ✅ 支持 | ✅ 支持 | 政企环境最常见 |
| Foxmail（IE/Edge 内核） | ❌ 不支持 | ❌ 不支持 | ✅ 支持 | ✅ 支持 | 截图即此客户端 |
| Outlook.com / 网页版 | ⚠️ 部分支持 | ⚠️ 部分支持 | ✅ 支持 | ✅ 支持 | 效果较好 |
| Gmail 网页/ App | ⚠️ 部分支持 | ✅ 支持 | ✅ 支持 | ✅ 支持 | 效果较好 |
| 手机自带邮件 App | 差异大 | 差异大 | ✅ 支持 | ✅ 支持 | 宽度受限 |

**关键结论**：要让所有客户端都能“居中 + 占屏宽 80%~90%”，最稳妥的做法是：
- **内层内容容器 table 直接写 `width="90%"`**（或 85% / 92%）
- **外层用 `<td align="center">` 包裹**
- **彻底抛弃 `max-width` 和 `margin:0 auto`**

### 2.3 为什么内容只占了屏幕一半

从截图和 HTML 综合判断，最可能的解释是：

1. 邮件客户端（Foxmail）在阅读窗格中渲染邮件时，外层 `<table width="100%">` 确实占满了阅读窗格的宽度；
2. 内层 `<table width="100%" max-width="680" ...>` 由于 `max-width="680"` 这个非法属性的存在，被某些渲染引擎错误解析为“该 table 不应该超过 680px”；
3. 同时 `margin:0 auto` 失效，table 默认左对齐；
4. 最终效果就是：内层内容 table 被限制在约 680px 且左对齐，看起来只占屏幕左半边。

也就是说，**问题不是“不够居中”，而是“宽度被非法属性限制 + 居中失效”同时叠加**。

## 四、可行方案对比

### 方案 A：百分比宽度 + 外层 align="center"（推荐）

**做法**：
- 外层 wrapper：`<table width="100%">` → `<tr><td align="center">`
- 内层 content table：`<table width="90%" align="center">`（删除 max-width 和 margin:auto）

**优点**：
- 所有邮件客户端都支持 `width="90%"` 和 `align="center"`
- 能达到占屏宽 90% 的目标
- 代码改动最小，只改 `_render_scheme_a` / `_render_scheme_b`

**缺点**：
- 在大屏幕（如 27 寸 2K/4K 显示器全屏阅读）下，行宽会非常长，阅读舒适性下降
- 表格内容（如周报里的 4 列表格）会被横向拉得很开

**兼容性**：⭐⭐⭐⭐⭐（最佳）

### 方案 B：双栏固定宽度 + 响应式条件注释（Outlook 专用）

**做法**：
- 对 Outlook 桌面版使用 `width="900"` 的固定宽度 table；
- 对现代客户端使用 `width="90%"`；
- 通过 Outlook 条件注释 `<!--[if mso]>` 区分。

**优点**：
- 能兼顾大屏幕下的阅读体验

**缺点**：
- 条件注释代码复杂，维护成本高
- 无法精确实现“占屏宽 80%~90%”在所有客户端一致

**兼容性**：⭐⭐⭐（较复杂，不推荐）

### 方案 C：保留 680px 固定宽度 + 强居中（不推荐）

**做法**：
- 把 `width="100%" max-width="680"` 改回 `width="680"`；
- 通过 `<td align="center">` + `<table align="center">` 双重居中。

**优点**：
- 阅读体验最好，行宽固定

**缺点**：
- 在宽屏上仍然只占屏幕中间一小块，不符合老大“基本全屏铺开”的要求

**兼容性**：⭐⭐⭐⭐

## 五、推荐方案：方案 A 细节设计

### 5.1 布局改造

```html
<!-- 外层：铺满邮件客户端阅读窗格 -->
<table width="100%" cellpadding="0" cellspacing="0" border="0" style="margin:0;padding:0;background:#ffffff;">
  <tr>
    <td align="center" style="padding:20px 0;">
      <!-- 内层：占屏宽 90%，邮件客户端 universally 支持 -->
      <table width="90%" align="center" cellpadding="0" cellspacing="0" border="0" style="background:#ffffff;">
        <!-- 抬头 -->
        ...
        <!-- 正文 -->
        ...
        <!-- 页脚 -->
        ...
      </table>
    </td>
  </tr>
</table>
```

**关键点**：
- 删除 `max-width="680"`
- 删除 `style="margin:0 auto"`
- 使用 `width="90%"` + `align="center"`

### 5.2 对表格类内容的保护

周报里有 Markdown 表格，如果容器宽度变成 90%，表格会被拉宽。需要：
- 表格单元格 `padding` 适当增加（如 10px 12px）
- 表格表头背景加粗，增强可读性
- 长文本单元格设置 `word-break:break-word` 防止撑爆布局

### 5.3 移动端适配

手机屏幕宽度有限，`width="90%"` 会自动收缩为屏幕宽度的 90%，配合 `word-break:break-word` 不会溢出。这是百分比宽度的天然优势。

## 六、抬头 Redesign 方案

### 6.1 当前抬头的问题

### 6.2 新抬头设计原则

- **专业**：去掉 emoji，使用文字和色块表达品牌
- **清晰**：一眼能看出“这是什么报告、谁发的、什么时间范围”
- **不重复**：每个信息只出现一次
- **层次分明**：标题最大，元信息次要，装饰最小
- **政企环境兼容**：避免圆角、渐变、阴影等 Outlook/Foxmail 不支持的效果

## 十、结论与下一步

### 10.1 结论

之前的优化无效，根本原因是：

1. 在 `<table>` 标签上使用了非法属性 `max-width="680"`；
2. 依赖了 Foxmail/Outlook 不支持的 `margin:0 auto`；
3. 没有使用邮件客户端 universally 支持的百分比宽度 + `align="center"`。

要实现“居中 + 占屏宽 80%~90%”，必须：

- **内层内容 table 直接写 `width="90%"` + `align="center"`**；
- **彻底删除 `max-width` 和 `margin:auto`**；
- **同步重设计抬头**，去除重复信息、emoji，增强专业性。

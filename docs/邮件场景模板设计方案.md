> 状态：**✅ 已完成（T-A~T-F 全部合版，2026-08-17）** | 日期：2026-08-17 | 关联：邮件发送能力统一规划设计方案.md

## 1. 现状诊断

### 1.1 SCENES 注册表（12 场景）

当前 `backend/services/mail_dispatch.py` 的 SCENES 注册表中，**全部 12 个场景均为 `raw=True`**，即正文由前端/后端代码构建 Markdown，后端只做 Markdown→HTML+签名注入，不走 3210 模板渲染。

### 1.2 3210 现有模板（5 个）

| 模板名 | type | 变量 | 格式 | SCENES 是否引用 |
|--------|------|------|------|----------------|
| 会议通知 | `meeting_notice` | meetingTopic, meetingTime, meetingLocation, host | html | ❌ scene 有此 key 但 raw=True |
| 任务督办提醒 | `task_reminder` | taskTitle, assignee, status, planEnd | html | ❌ scene 有此 key 但 raw=True |
| 需求催办通知 | `xqemail_reminder` | reqId, reqName, saName, proposeTime, items | text | ❌ |
| 需求评估通知 | `req_eval` | 需求编码, 需求名称, ... (中文键) | text | ❌ |
| Obsidian笔记同步 | `obsidian_note` | title, content | html | ❌ |

### 1.3 核心问题

1. **模板与场景脱节**：3210 有 5 个模板但 SCENES 一个都没引用，全部走 raw markdown
2. **变量命名不统一**：camelCase（reqId）与中文（需求编码）混用
3. **正文逻辑分散**：前端 6 个 .vue 文件各自 `buildBody()`，后端 3 个 service 各自拼正文
4. **运营模块遗漏**：WorkOrderView/RequirementDeliveryView 原用独立 SuperviseDialog，P2 已收口

### 1.4 3210 模板服务能力确认（2026-08-17 实测）

| 能力 | 端点 | 结论 |
|------|------|------|
| 创建模板 | `POST /api/templates` | ✅ 必填 `name`/`type`/`subjectTemplate`/`bodyTemplate`，可选 `bodyFormat`(`html`/`text`)/`description`/`isDefault` |
| 更新模板 | `PUT /api/templates/:id` | ✅ 局部更新 |
| 删除模板 | `DELETE /api/templates/:id` | ✅ |
| 渲染模板 | `POST /api/templates/:id/render` | ✅ 请求 `{"variables":{...}}` → 返回 `{subject, body, bodyFormat}` |
| 变量插值 | `{{var}}` | ✅ HTML 转义输出 |
| 原始 HTML | `{{{var}}}` | ✅ 原样输出（供 content/列表块透传） |
| 条件/循环 | `{{#if}}` `{{#each}}` `{{#actionItems}}` | ❌ **不支持**，原样输出残留文本 |

> **模板引擎铁律**：模板内只能用 `{{var}}` / `{{{var}}}` 两种插值；**禁止块级 helper**。
> 条件分支（催办/同步）→ 调用方传不同变量（如 `sceneLabel`）；列表 → 调用方格式化为字符串/HTML 后传入。
> `subject` 支持前端覆盖：`final_subject = subject or rendered_subject`（前端 MailComposeDialog 传了 subject 即优先）。

### 1.5 调用方现状（后端 service 传参）

| 调用方 | 位置 | 当前传参 | 模板化改造 |
|--------|------|---------|-----------|
| meeting.py action_dispatch | `meeting.py:225` | `body=md` | → `variables={meetingTitle, actions, body}` |

## 3. 变量命名规范

### 3.1 统一规则

- **所有变量使用 camelCase**：如 `meetingTitle`、`reqId`、`saName`
- **禁止中文变量名**：3210 现有 `req_eval` 模板使用中文键（需求编码、需求名称），需重构为 camelCase
- **日期格式**：统一 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm`
- **列表变量**：传入格式化好的字符串（3210 模板引擎不支持循环）

## 5. 风险与约束

1. **3210 模板引擎限制**：仅支持 `{{var}}`/`{{{var}}}` 插值，**不支持条件分支和循环**（2026-08-17 实测）；列表/条件一律在调用方处理

## 2. 根因分析（5 层）

### R1 流程层 —— 已有「AI 自动提交/推送」规则未被执行（主因，非"无规则"）
- **关键澄清**：提交与推送规则此前**早已确立且明确由 AI 自动按需直接执行**——2026-07-30 统一开发执行模型（"AI 自己也是开发者，可直接接任务写代码"）、2026-08-08「审查通过自动推 origin，无需确认」、2026-08-15 夜间「浮动改动必提交」。因此本次**不是缺少规则，而是规则未被可靠执行**。
- 8/15 当天 git 仅 2 个 commit，前几天所有功能（首页看板 db-1~5、kc4 知识中心、AI中心、重点工作导入等）**全部是未提交浮动改动**，无历史、无回滚点——证明规则在当天实操中被绕过。
- **为何会被绕过（诚实子因）**：
  1. **共享可变工作树 + 多 AI 并发**：每个 AI 只敢提交"自己那部分"，对他人浮动改动采取"保留不碰"策略，导致跨会话/跨 AI 的工作长期游离在 git 之外。
  2. **救火优先于提交**：8/15 是连续抢险（功能被删/降级），优先级是"先跑起来"，提交被反复推迟，每次恢复后又立即投入下一轮抢险，浮动越积越多。
  3. **"完成"定义错位**：把"本地能跑/接口 200/页面渲染"当作完成，违背了"无 commit = 未完成"的硬规则。
  4. **安全提交流程摩擦**：为规避沙箱孤儿分支怪象，提交必须用繁琐的单命令法，心理上有"能攒就攒"的倾向，反而放大单次丢失面。
- 后果：`git revert/reset/checkout/fsck` 只能回到 commit 状态，浮动改动从未 `git add`，删了即真没；12:37 全树备份也是 git archive，不含未提交内容。

### R2 协作层 —— 多 AI 共享可变工作树、无隔离（放大器）
- 多 AI 共用一个工作树，`reset --mixed` / `checkout` / 覆盖操作互相打架，导致文件被降级为旧版（而非完整删除），难以察觉。
- OWNERSHIP 文件分工未真正串行化，存在并发覆盖窗口。

### R3 工具/环境层 —— 沙箱 git 孤儿分支怪象（chronic 环境缺陷）
- `git checkout -b` / `git branch` 等分支操作在沙箱偶发把 `.git/refs/`、`git/logs` 清空、本地 main ref 丢失（远端完好）。
- **grep 实证该问题自 8/01 起反复出现**：`.workbuddy/memory/` 中 2026-08-01 / 08-04 / 08-08 / 08-10 / 08-14 / 08-16 均记载同类坑。属系统性环境缺陷，非本次独有。

### R4 工程层 —— 测试-生产 gap 与可拦截回归
- **死测试掩盖功能蒸发**：`test_business_timeline` / `test_main_note_sync` / `test_requirement_deliverables` 长期 collection ERROR，但无人跑全量或无人看 collection error，导致三块功能代码蒸发数月未被发现。
- **Feature3 编辑误删 `requirement_service` 导入**：导致整个需求路由运行时 `NameError`、16 个需求测试全红。这类"import 完整性"问题本可在 pre-commit 用一次启动探测拦截。

### R5 安全网缺口 —— WIP 每日自动提交（次要兜底）仍缺失
- 8/15 收尾曾约定「建立每日 WIP 自动提交」作为兜底安全点，但**核验现状**：当前仅 2 个自动化（`审查退回任务每日扫描 09:00`、`PMWB 临时文件定时清理 周五 12:00`），**该 WIP 自动化从未落地**。
- **重新定位**：WIP 自动提交是**次要兜底**，不是主因——主因是 R1 的已有自动提交规则未被执行。但鉴于共享工作树 + 多 AI 场景下"done"边界模糊、易于漏提交，**WIP 兜底仍有价值**，可在主规则之外兜住漏网之鱼。
- 时间修正：原议 23:00，但您的电脑彼时大概率关机；改为**每日 13:40**（工作时段、电脑在线），`git add -A && git commit -m "WIP <date>"`（仅本地，不 push 到远端以免污染历史）。

## 5. 整改方案（确保今后不再发生，分层 + 优先级 + 触发条件）

### A. 严格执行已有「AI 自动提交/推送」规则（P0，主防线）
- **主防线就是既有规则本身**：AI 完成一个可交付改动即走 feature 分支提交并 push origin（审查通过自动推），**禁止把"本地能跑"当完成**——`no commit = not done` 必须成为每轮收尾的硬卡点。
- **消除提交摩擦**：把单命令法封装成 `scripts/git-safe-commit.sh`（入参：文件列表 + message），让"安全提交"变成一条命令，消除因规避孤儿分支怪象而产生的"能攒就攒"心理。
- **WIP 兜底（次要，13:40）**：补建「每日 13:40 WIP 自动提交」自动化（`git add -A && git commit -m "WIP <date>"`，仅本地不 push），兜住共享工作树下跨会话/跨 AI 漏提交。→ 时间已按您电脑作息从 23:00 改为 13:40。

### B. 规避沙箱 git 孤儿分支怪象（P0）
- **严禁** `git checkout -b` / `git branch` / `git worktree`；一律走单命令法（`symbolic-ref HEAD→reset --mixed→add 精确路径→commit→push origin main`）。
- 把单命令法固化成仓库脚本（如 `scripts/git-safe-commit.sh`，入参：文件列表 + message），杜绝手抖触发孤儿分支。
- 任何 git 操作前先 `cp -r 仓库外备份 /d/fixbk_<timestamp>` 作为最后防线，并制度化（目前仅偶发手工做）。

### C. 防"功能蒸发 / 死测试"门禁（P1）
- 每次 push 前跑 `pytest --collect-only` 确认 0 collection error；全量 pytest 必须 0 fail 才允许 push（质量门禁已有，需自动化卡点而非靠人看）。
- 周级扫描「测试引用符号 vs 当前代码库存在性」：凡测试 import/调用某函数而该函数不存在，立即告警，避免功能被删但测试仍被忽略。
- 前端同理：路由/菜单/组件引用一致性自检。

### D. 预提交静态校验（P1）
- **后端 import 烟雾测试**：提交前 `python -c "from backend.main import app"` 必须成功，否则拦截——可直接防住"整路由 `NameError`"（如 requirement_service 误删）。
- 密钥扫描 + Grep 关联点，复用现有收尾规则。

### E. 单一可信回滚源（P1）
- 废弃"从各种 `_*_backup` 盲恢复"做法（版本漂移导致恢复即坏，如 `render_auto_block` 案例）。唯一可信源 = git（含每日 WIP 提交）+ `origin/main`。
- 仓库外全树 tar 仅作兜底，不以备份作为回滚依据。

### F. 多 AI 协作隔离（P2，长期）
- 如可行，给每个 AI/任务切独立 worktree 或独立分支，避免共享工作树互相覆盖；沙箱不支持则退而求其次：OWNSHIP 文件 + 任务串行化。

### G. 监控与告警（P1）
- 每日 13:40 WIP 提交 + 每日 09:00 扫描 `git status` 是否有超 24h 未提交的浮动改动并提醒老大（复用现有 09:00 扫描自动化思路）。
- 提交后自动 restart 服务并 curl 关键端点，失败即告警（健康巡检）。

## 8. 直接回答：为何已有「自动提交」规则，仍出现未提交改动

您指出的问题切中要害——规则（2026-07-30 执行模型 / 2026-08-08 自动推 / 2026-08-15 浮动必提交）确实早已明确"AI 自动按需直接提交推送"，那为什么 8/15 仍出现大量未提交浮动改动？诚实复盘如下：

1. **规则在执行层被绕过，而非不存在**。8/15 当天仅 2 个 commit，说明"自动提交"在当天的连续抢险中没有被当作每步收尾的硬卡点执行。
2. **多 AI 共享工作树制造了"不敢提交他人改动"的困局**。每个 AI 只提交自己那部分、保留他人浮动改动，导致跨会话工作长期游离于 git 之外——这是协作架构缺陷，不是单条规则能解决的。
3. **抢险节奏压倒了提交纪律**。"先跑起来"优先，提交被一推再推，恢复完一波立刻投入下一波，浮动越积越多直到灾难发生。
4. **"完成"定义错位 + 提交摩擦**。把"本地能跑"当完成，违背了 no-commit=not-done；而规避孤儿分支怪象所需的安全提交流程较繁琐，客观上助长了"攒一批再交"。

**结论**：根因不是"缺规则"，而是"规则未被可靠执行 + 共享树协作模型让执行变难 + 提交有摩擦"。因此整改重心应放在**让既有规则易执行、强执行**（封装 git-safe-commit、no-commit=not-done 硬卡点），WIP 每日自动提交只是兜漏网的二线手段（且已改到 13:40 适配您电脑作息）。
